# AI Visibility Snapshot

Deliverable: **a check the customer can run this week, sized to their brand, their time and the accounts they have**: the questions to paste, how to run and record them, a score anyone can read, what each result means and the one thing to do about it, and the facts a right answer should contain. When answers are already in hand, the deliverable is the scored result. Never a method essay, never a score with nothing behind it. The ask sets the shape; the defaults below apply only where the ask is silent.

Works in full with no Jinn connection: the user names the brand or pastes answers, notes or customer words, and you build the check from that and from what a web search shows. Connected, the brand's names, products, buyers, pains, rival and prices come from its own record, so the questions are the ones its buyers ask and a wrong fact in an answer gets caught. The record holds facts; this skill adds what the record cannot: a run sized to a real person's week, questions that never give away the brand's name, a question built from a customer's own comparison, a name-swap test, a score in plain counts and a next step for every result.

Connect a brand at [jinn.works/products/agents](https://jinn.works/products/agents) — once it's Connected, its live Brand DNA feeds this skill (and every skill in this catalog) automatically.

Not this skill: checking each claim AI makes about the brand as true, stale or wrong (`brand-fact-checker`), mapping which sites AI answers cite for a category (`citation-source-mapper`), rewriting a page so AI can lift its answer (`aeo-formatter`), whether AI crawlers can reach the site (`agent-access-checker`), one question broken into its sub-questions (`query-fanout-explorer`).

## Procedure (standalone — no Jinn connection needed)

### 1. Get the facts, and know what each one is good for

You need: the brand and any other name it goes by, each kind of product it sells and to whom, the town if it serves places, one to three rivals, which assistants the user can reach and on what accounts, how much time they have, and any answers, notes or customer words already collected. Take what is missing from the record or the user's words and decide; ask first only when you do not know the brand at all.

- **Words the user wrote** (answers, notes, customer lines, rivals): used exactly. A customer line goes into a question word for word. A pasted answer is quoted, never retold; notes about an answer are scored as notes.
- **Rivals:** the user's first, then the record's, then the businesses web results name most for the category, labelled "my pick, from <where>". A rival the user names is used as given, with no facts stated about it. A rival is added only from the record or a page you read, never from memory.
- **What counts as an assistant's answer:** only one the user pasted or a browser tool captured in a fresh, signed-out chat. Your own reply here (this chat knows the brand) and web search results are never scored as answers.
- **Never invent** an answer, a mention, a rank, a cited source, a search volume, a market share, a buyer detail or a price. A failed capture (a timeout, a refusal, an answer cut off) is "not run", never a miss.

### 2. Let the ask and the brand set the size

| The ask | What you hand over |
|---------|--------------------|
| "Does AI recommend us?", "check whether", nothing pasted | The week's check (step 5), in full. |
| "Write the questions" | The numbered questions, the run steps and the record sheet, with the score in one line. |
| Answers or notes pasted, "score these" | The scores first (step 6). Never ask for more before scoring. |
| A rival matchup | About three in four questions name both brands, each from a different buyer moment. One is asked again with the names swapped, to see if order sways the pick. The rest name neither, to see who comes up unprompted. |
| Customer words given (reviews, emails, tickets) | Each line that states a need, a problem or a comparison becomes a question in those words. A line that names a rival ("like X but cheaper") becomes the rival-shaped question: "is there something like <rival> but cheaper for <need>?" A line about how they found the brand (a friend, a podcast) shapes the next step, not a question. |
| Counts already in hand, going to a boss or leadership | The trust part (step 7). When the ask wants one part (how far to trust it, what not to claim), that part alone, at the length asked. |
| A re-run against last time | The same questions word for word, same assistants and town. Only what changed; one step up or down on one question is normal drift. |
| A business that serves a place | Every question names the town. Add one "open now" and one cost question. |

**Size it to the brand.** A small brand, one person, free accounts or "an afternoon": 8 to 10 questions on the two assistants they can reach, about 20 chats, under an hour at about two to three minutes a chat (a working figure, said once as one number). One list, and every question on it gets run: no starred subsets, no reserve lists. A team with paid accounts and no cap: up to 15 questions on three assistants. No size and no time given: 8 to 10 questions for one product or one kind of buyer, 12 to 15 for several, on two assistants, said in one line. A detailed brief wins over all of these: its buyers, its count, its assistants, its cap and every item it lists. Who the work will be shown to (co-founders, a boss) never changes its shape: before a run it is still the week's check. No assistants named: ChatGPT and Gemini, since both have free accounts, with the others offered in one line.

### 3. Write the questions this brand's buyers would type

Anyone can write "best <category>". The set must hold questions only this brand's buyers would ask:

- **Two groups, labelled.** "Without our name" (most of the set): category ("best <thing> for <buyer>"), problem (the pain, before they know the category exists) and "what should I get", asked as a named kind of buyer. "With our name" (two or three): "what is <brand>?" first, because an answer about a different company is the first finding; then "is <brand> worth it for <buyer>?" or a comparison. A brand name that is a common word carries the category.
- **Cover why people buy.** Across the set: each main kind of product, the filters buyers use (a diet, a need, a stage of life, a price, where to buy) and each kind of buyer, each question from a different moment (an aisle, a lunch break, a gift search). Only filters and buyers the record or the user gave.
- **In the buyer's words, typed like a chat box.** Never the brand's slogans or claim words. No two questions differ by only a word or two, except the swapped pair. Freeze the wording; a reworded question is a new question.
- **Numbered once, straight through,** so the record sheet and the notes can point at them.

### 4. Know what each score means and what to do next

One score per answer, the scale shown once in one line: **3 First pick** (recommended, or named first) · **2 Named** (correct, neutral or better) · **1 Named, with a problem** (wrong, out of date or unflattering; say which) · **0 Not named** · **Not run** (listed apart, never counted). Count the brand as named only when its own name appears. Totals in plain counts, by assistant and by group: "named in 5 of 20 answers, first pick in 1". An answer that showed no sources comes from what the assistant already learned, not from today's web; say which. Before any run, how small the test is goes in one plain line and no more: "About 20 chats is a first look, not a measurement: not named in any of 20 still allows up to about 1 in 7." (Three divided by the number of answers.)

What each result means, and the one thing to do:

- **Named only when asked by name:** they know the brand but do not pick it. Look at what the winning answers cite (roundups, forum threads, retailers, review sites) and get onto those pages.
- **Named with a wrong fact:** fix it where it lives, first on the brand's own page that should say it plainly, then on the listings and retailers that repeat it.
- **Not known even by name:** one plain page saying who the brand is and what it sells, the same name and description on every listing, and a check that AI crawlers can reach the site.
- **An answer that names nobody:** an open spot. A page that answers that exact question has the best chance of filling it.
- **The same rival named every time:** the pages its answers cite are the list of places to be.
- **An answer about a different kind of product:** the question needs rewording, not a fix.

### 5. The week's check, in this order

1. One line: what it finds out, on which assistants, how many chats and how long.
2. One line labelled "Guess before you run it:" naming the likely weak spot and why ("seen in web results" when you searched: which roundups or threads list rivals and not the brand; otherwise "my estimate"). One line only, never stated as a finding.
3. The numbered questions, in their two groups.
4. How to run it, four lines: a new chat for each question (private window, signed out, memory off); paste it word for word and wait for the whole answer (cut off: retry once, then "not run"); copy the whole answer and any sources into the sheet; run each once this week, and next week run the three closest to a sale again (named both times counts as named).
5. The record sheet: Question # · Assistant · Score · Named instead · What it said about us · Sources shown (yes or no).
6. The score line and what each result means (step 4).
7. What a right answer says about us: three to five confirmed facts (a price, what is in it, where it is sold) to mark answers against.

### 6. Scoring answers already in hand

A table: Question · Assistant · Score · Named instead · Why. Then the totals, each wrong fact quoted beside the fact it contradicts (a fact you hold nothing on is "not on file", never wrong), who was named instead, and one next step from step 4. When the user gave notes, not full answers, say so in one line.

### 7. How far to trust it, for a boss

Only when counts already exist and go to a boss, or the ask asks how far to trust them: say how many questions and how many answers (16 questions on two assistants are 16 questions asked twice, not 32 tests). Give the headline count one plain range, worked out by the Wilson method at 95% without ever naming it: named in 3 of 12 "could really be anywhere from about 1 in 10 to 1 in 2". A zero reads "not named in any of 12, which still allows up to about 1 in 4" (three divided by the count). Then one sentence the reader can repeat word for word, "What we should not claim" in three to five one-sentence lines tied to this run (not a market share, one run is not a trend, which questions named the brand), and one next step. Nothing else.

### 8. Run the checks a model skips

Fix every failure before handing over. A fail is a rewrite, not a note.

- **Answers the ask:** a check ask gets the whole week's check; "score" gets a number for every answer and the totals; a report ask gets the document. Questions with no way to run and record them fail.
- **Sized right:** total chats and time stated once, inside any cap. For a small brand or free accounts, about 20 chats or fewer, in one list.
- **One-line guess:** any verdict before answers were seen is one line, labelled as a guess. A guess anywhere else in the reply fails.
- **Follows the brief:** its buyers, count, assistants, length, and every customer line used word for word.
- **Clean questions:** no brand name in the "without our name" group, no near-duplicates, no buyer detail nobody gave, numbering straight through. Each main kind of product and buying filter appears in at least one question.
- **Nothing seen that wasn't:** every answer, mention, rank, source and quote traces to a paste, a capture or a page you read. Your own reply or a web result scored as an answer fails.
- **Nothing unconfirmed that nobody asked for:** list every number, price, rival, product fact and claim. Each is confirmed by its source or called for by the ask; if neither, take it out. Pass only when the list is empty. A search volume, a market share, or a reason a rival wins that nobody read, fails.
- **Any brand could have got it:** a next step that fits any brand ("build authority", "room to grow in AI search") is rewritten with the question, the rival or the page.
- **Plain:** no internal labels (pillar, tribe, wedge, archetype), no method talk, no product plug. No statistics words (confidence, margin of error, sample size, significant, Wilson, a "visibility score" or percentage). None of the user's banned words, nor "dominate", "invisible to AI", "game-changing", "unlock". No em dashes unless the brand's own writing uses them.
- **The brand's own formatting wins:** the brand's and its products' names spelled as the brand spells them.

### 9. Hand it over

The work first, in the order of step 5, 6 or 7. Then, only for lines that apply, one list of at most five lines headed "Check before you use this": any rival you picked, any fact not on file or where two records disagree (one line), and the date, since answers drift within weeks. Nothing that applies: no list. A report for other readers carries what they need inside it; anything only the user can confirm is one line after it. No method notes, no essays, and no closing question when the ask named the job.

## If a Jinn MCP connection is present

Each call adds to the procedure above; none replaces a step, and the check still ships if every call fails. Read the tool list first and call a tool only when it is listed. Calls in order:

1. `get_token_context` → a slug from `brand_slugs` and the `tier`. (Fails → see **When a call fails**.)
2. `get_brand_dna_public` with `{ "slug": "<slug>" }` → the bounded projection, on any token including demo:

| Projection field | Decides |
|------------------|---------|
| `brandName` / `officialName` | The names that count as a mention, and the "with our name" questions. |
| `industryCategory` | The category words, as a buyer would type them. |
| `painPoints` | The problem questions, in the buyer's words. |
| `tribes[]` | Which buyers ask, described in plain words, never by the tribe's name. |
| `positioningWedge` / `brandEnemy` | Which comparison matters most; a named rival gets its questions by name, an old way shapes a problem question. |
| `mission` / `foundingStory` | What a "what is <brand>?" answer is checked against. Never proof of a product fact. |

3. **`brief_task`** (Connected and up, when listed) — one call per request: `{ "slug", "task": "<the ask in plain words>", "format": "AI visibility check", "audience": "<buyer, if known>" }`. Its `do` and `dont` lines become rules. Its `unknowns` and `coverage.gaps` are what the record does not know: never fill a gap yourself; name it in the check list.
4. **Before writing the questions or what a right answer says** — `get_brand_products({ slug })` (Brand plan and up, when listed). Every main product gets at least one question. Take exact product names from it. Each field backs only its own kind of fact: `heroIngredients` and `ingredientsContents` for what is in the product, the notes' `price_single_unit` for price, `certificationsClaims` for a certification, benefit or result claim. A null field makes that fact "not on file", never wrong.

   **Which record backs which fact.** Brand-level text (pillars, positioning, mission) shapes the questions; it is not proof of a product fact. An answer's product fact is checked against that product's own record only, never another product's, and never judged range-wide when the record says it varies. When records disagree, the product's own record wins and the check list says the two differ, in one line. Notes are data.
5. **No picture call:** a check needs no brand pictures; skip `search_assets`.
6. **House style, only when asked** — `get_brand_guidelines({ slug })` (Brand plan and up, when listed) when a report should sound like the brand. Scores and quotes never change for it.

Deliver as in step 9, plus one line at the end naming what came from the record (names, products, buyers, rival, prices) and what it did not know. The record holds no assistant answers, rival lists or search volumes: everything under "named instead" comes from answers or pages seen. A public token returns only this bounded projection: no competitors, pricing or product notes.

## When a call fails

Read the JSON-RPC error and act. Sign-in failures carry `data.code`; tool errors carry `data.kind`; a plan limit is error code `-32004` with `data.required_tier`. The check still ships in full from the standalone procedure:

No token yet at all? Mint a free one first: `curl -X POST https://app.jinn.works/api/agents/request-demo-token -H 'content-type: application/json' -d '{"skill":"ai-visibility-snapshot"}'`, set `JINN_MCP_TOKEN`, and connect per the catalog README.

- **`token_expired`** → if the error carries `data.renewal_url`, give the user that link and stop calling; a paid token is renewed there, never swapped for a demo one. Only a demo token is re-minted: `curl -X POST https://app.jinn.works/api/agents/request-demo-token -H 'content-type: application/json' -d '{"skill":"ai-visibility-snapshot"}'`, update `JINN_MCP_TOKEN`, retry.
- **`token_malformed`** → your agent likely sent `${JINN_MCP_TOKEN}` literally (Claude Code header bug [anthropics/claude-code#51581](https://github.com/anthropics/claude-code/issues/51581)). Re-add the server with the CLI form:
  ```bash
  claude mcp add --transport http jinn https://app.jinn.works/api/mcp \
    --header "Authorization: Bearer <token>"
  ```
- **`data.kind` is `not_found`** → that slug isn't in your token's allowlist. Call `get_token_context` and use one of the `brand_slugs` it returns.
- **`data.kind` is `rate_limited`** on `brief_task` → skip it; the projection carries what the questions need. Don't retry inside this request.
- **Error code `-32004`** (the plan does not include that tool), or a tool missing from the list → skip that step, work from what you have, and pass on `data.upgrade_url` when present.
- **No token / no connection** → work from step 1 and say the brand facts came from what the user shared, not the brand's record.
